## 已确认的核心问题

### 1. 订单管理页报错的直接原因
后端订单明细实体 [`OrderItem`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/entity/OrderItem.java:11) 映射了字段 `price`，而建表脚本 [`schema.sql`](back/e-commerce-back/src/main/resources/sql/schema.sql:77) 里 [`order_item`](back/e-commerce-back/src/main/resources/sql/schema.sql:77) 表确实定义了 `price` 列。

这说明问题更可能是：
- 运行中的数据库表结构和当前代码库里的 [`schema.sql`](back/e-commerce-back/src/main/resources/sql/schema.sql:77) 不一致
- 或历史数据库缺少 `order_item.price` 列

订单管理接口 [`getAllOrders`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/service/OrderService.java:160) 在循环加载订单项时，调用了 MyBatis-Plus 的 [`selectList`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/service/OrderService.java:178)，会按实体字段查询 `price`，因此数据库缺列就会直接报错。

### 2. 前端订单模块与后端接口明显不一致
前端订单 API 文件 [`order.ts`](front/e-commerce-platform-front/src/api/modules/order.ts:1) 与后端 [`OrderController`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/controller/OrderController.java:15) 不匹配：

- 前端 [`getOrderDetailAPI`](front/e-commerce-platform-front/src/api/modules/order.ts:11) 调 `/order/${id}`
  - 后端实际是 `/api/order/detail/{orderNo}`，见 [`detail`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/controller/OrderController.java:50)
- 前端 [`cancelOrderAPI`](front/e-commerce-platform-front/src/api/modules/order.ts:15) 调 `POST /order/cancel/{id}`
  - 后端实际是 `POST /api/order/cancel` 且 body 需要 `{ orderNo }`，见 [`cancel`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/controller/OrderController.java:59)
- 前端 [`confirmReceiveAPI`](front/e-commerce-platform-front/src/api/modules/order.ts:19) 调 `/order/confirm-receive`
  - 后端当前不存在该接口
- 前端订单列表 [`getOrderListAPI`](front/e-commerce-platform-front/src/api/modules/order.ts:7) 调 `/order/list`
  - 后端虽然有 `/list`，但只返回基础订单列表；而多个前端页面实际依赖 `orderItems`
  - 后端真正返回带订单项数据的是 [`/my-list`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/controller/OrderController.java:41)

### 3. 购物车模块也有明显接口不一致
前端 [`cart.ts`](front/e-commerce-platform-front/src/api/modules/cart.ts:15) 删除购物车使用 `DELETE /cart/remove/{id}`。
后端 [`CartController`](back/e-commerce-back/src/main/java/com/example/ecommerceback/cart/controller/CartController.java:55) 实际提供的是 `POST /api/cart/delete`，body 结构是 `{ ids: [...] }`。

这会导致购物车删除功能失败。

### 4. 管理后台接口整体基本对齐
前端 [`admin.ts`](front/e-commerce-platform-front/src/api/modules/admin.ts:123) 与后端：
- [`AdminOrderController`](back/e-commerce-back/src/main/java/com/example/ecommerceback/admin/controller/AdminOrderController.java:14)
- [`AdminProductController`](back/e-commerce-back/src/main/java/com/example/ecommerceback/admin/controller/AdminProductController.java:14)
- [`AdminUserController`](back/e-commerce-back/src/main/java/com/example/ecommerceback/admin/controller/AdminUserController.java:14)

整体路径基本一致，订单管理页当前更大的阻塞点不是路由不匹配，而是数据库结构与订单查询链路。

## 建议实施方案

### 步骤 1：先修复数据库与订单明细结构不一致
目标：让订单管理页先恢复可用。

建议修改或补充：
- 新增数据库修复 SQL，确保 [`order_item`](back/e-commerce-back/src/main/resources/sql/schema.sql:77) 至少包含：
  - `id`
  - `order_id`
  - `product_id`
  - `product_name`
  - `price`
  - `quantity`
- 如有必要，补充兼容性脚本到：
  - `back/e-commerce-back/` 下新增修复 SQL 文件

说明：
当前报错更像运行库遗留问题，不是 Java 实体本身定义错误。实施时应优先补数据库修复脚本，而不是删掉 [`OrderItem.price`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/entity/OrderItem.java:24)。

### 步骤 2：统一前端订单 API 到后端真实接口
建议修改文件：
- [`front/e-commerce-platform-front/src/api/modules/order.ts`](front/e-commerce-platform-front/src/api/modules/order.ts:1)

具体调整：
- 将 [`getOrderDetailAPI`](front/e-commerce-platform-front/src/api/modules/order.ts:11) 改为调用 `/order/detail/${orderNo}`
- 将 [`cancelOrderAPI`](front/e-commerce-platform-front/src/api/modules/order.ts:15) 改为 `POST /order/cancel` 且 body 为 `{ orderNo }`
- 将订单列表接口改为优先调用 `/order/my-list`，保证前端拿到 `orderItems`
- 对 [`confirmReceiveAPI`](front/e-commerce-platform-front/src/api/modules/order.ts:19) 二选一：
  1. 后端补 `/order/confirm-receive`
  2. 前端暂时移除或禁用确认收货入口

从完整性角度，建议补后端接口。

### 步骤 3：补齐后端确认收货接口
建议修改文件：
- [`back/e-commerce-back/src/main/java/com/example/ecommerceback/order/controller/OrderController.java`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/controller/OrderController.java:15)
- [`back/e-commerce-back/src/main/java/com/example/ecommerceback/order/service/OrderService.java`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/service/OrderService.java:25)

建议实现：
- 新增 `/api/order/confirm-receive`
- 校验当前用户、订单归属、订单状态
- 将状态更新为“已完成”

这样能和前端 [`OrderList.vue`](front/e-commerce-platform-front/src/views/order/OrderList.vue:152) 以及 [`OrderDetail.vue`](front/e-commerce-platform-front/src/views/order/OrderDetail.vue:237) 的交互闭环保持一致。

### 步骤 4：统一购物车删除接口
建议修改文件：
- [`front/e-commerce-platform-front/src/api/modules/cart.ts`](front/e-commerce-platform-front/src/api/modules/cart.ts:1)
- 如有调用方需要联动，再检查：
  - [`front/e-commerce-platform-front/src/views/cart/Cart.vue`](front/e-commerce-platform-front/src/views/cart/Cart.vue:1)
  - [`front/e-commerce-platform-front/src/store/cart.ts`](front/e-commerce-platform-front/src/store/cart.ts:1)

具体调整：
- 将前端删除接口改为调用 `POST /cart/delete`
- body 改成 `{ ids: [id] }` 或支持批量删除的数组形式

### 步骤 5：检查订单页面的数据消费方式
建议复核文件：
- [`front/e-commerce-platform-front/src/views/order/OrderList.vue`](front/e-commerce-platform-front/src/views/order/OrderList.vue:90)
- [`front/e-commerce-platform-front/src/views/order/OrderDetail.vue`](front/e-commerce-platform-front/src/views/order/OrderDetail.vue:164)
- [`front/e-commerce-platform-front/src/views/admin/OrderManagement.vue`](front/e-commerce-platform-front/src/views/admin/OrderManagement.vue:132)
- [`front/e-commerce-platform-front/src/views/dashboard/Dashboard.vue`](front/e-commerce-platform-front/src/views/dashboard/Dashboard.vue:42)

重点确认：
- 是否统一按 `res.data` 或 `res.data.list` 读取
- 是否假设每条订单都含 `orderItems`
- 是否在订单详情页把返回结构当作 `order` 本体，而后端其实返回的是 [`OrderDetailDTO`](back/e-commerce-back/src/main/java/com/example/ecommerceback/order/service/OrderService.java:257)

这里很可能还存在第二层问题：
后端详情接口返回 `{ order, items }`，但前端详情页大概率按单个订单对象直接消费，需要一起修正返回处理逻辑。

## 建议的执行清单

1. 修复运行数据库的 [`order_item`](back/e-commerce-back/src/main/resources/sql/schema.sql:77) 表结构，补齐 `price` 列
2. 修正前端 [`order.ts`](front/e-commerce-platform-front/src/api/modules/order.ts:1) 的路径与请求体
3. 在后端补充确认收货接口，并复用订单状态流转逻辑
4. 修正前端 [`cart.ts`](front/e-commerce-platform-front/src/api/modules/cart.ts:1) 删除接口与请求格式
5. 联调订单列表、订单详情、管理员订单页、购物车删除功能
6. 若发现详情返回结构不匹配，再同步修正前端页面的数据解包逻辑

## 方案结论

这次不建议只盯住订单管理页单点修复，而应按“数据库结构修复 + 订单接口对齐 + 购物车接口对齐”的方式一次性处理，否则前端多个页面仍会持续报错。

如果你认可这套方案，下一步应退出规划并切换到 `code` 模式实施，优先顺序为：数据库兼容修复、订单接口修复、购物车接口修复、页面联调。
