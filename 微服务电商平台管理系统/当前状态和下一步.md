### 第一步：确保数据库正确 ⭐⭐⭐

**为什么重要：** 如果数据库中没有用户或密码不对，登录肯定会失败

**操作步骤：**

1. 打开 MySQL 客户端（Navicat、MySQL Workbench 或命令行）

2. 运行这个文件：`back/e-commerce-back/重新初始化用户表.sql`

3. 确认看到 3 个用户：
   - admin / 123456 / admin
   - test / 123456 / user
   - user1 / 123456 / user

**如何运行 SQL：**

**方法 1 - 使用 Navicat：**
- 打开 Navicat
- 连接到 MySQL
- 打开 `重新初始化用户表.sql` 文件
- 点击"运行"按钮

**方法 2 - 使用命令行：**
```bash
mysql -u root -p < back/e-commerce-back/重新初始化用户表.sql
```

**方法 3 - 使用 MySQL Workbench：**
- 打开 MySQL Workbench
- 连接到数据库
- File → Open SQL Script → 选择 `重新初始化用户表.sql`
- 点击闪电图标执行

### 第三步：使用 HTML 测试页面测试后端 ⭐⭐⭐

**为什么用 HTML 而不是前端：** HTML 页面更简单，可以排除前端的问题

**操作步骤：**

1. 用浏览器打开文件：
   ```
   back/e-commerce-back/test-login.html
   ```
   
   **如何打开：**
   - 在文件资源管理器中找到这个文件
   - 右键 → 打开方式 → 选择浏览器（Chrome、Edge 等）
   - 或者直接拖到浏览器窗口

2. 确保表单中填写的是：
   - 用户名: `admin`
   - 密码: `123456`

3. 点击 **"测试登录"** 按钮

4. 查看结果区域

**预期结果（成功）：**
```
登录响应:
状态码: 200
响应数据: {
  "code": 200,
  "message": "登录成功",
  "data": {
    "id": 1,
    "username": "admin",
    "role": "admin",
    ...
  }
}

✅ 登录成功！现在可以点击"获取用户信息"测试Session
```

**如果失败，可能看到：**
- 状态码 500 → 后端有异常
- 状态码 401 → 用户名或密码错误
- 状态码 404 → 后端没启动
- 网络错误 → 后端没启动或端口不对

5. 如果登录成功，点击 **"获取用户信息"** 按钮

**预期结果（成功）：**
```
用户信息响应:
状态码: 200
响应数据: {
  "code": 200,
  "data": {
    "id": 1,
    "username": "admin",
    "role": "admin",
    ...
  }
}

✅ Session 正常工作！
```

## 🔍 根据测试结果判断问题

### 情况 1: HTML 测试登录失败（500 错误）

**问题：** 后端代码有异常

**需要的信息：**
- IDEA 控制台的完整异常堆栈

**可能原因：**
- 数据库连接失败
- User 实体类字段不匹配
- UserMapper 查询失败

---

### 情况 2: HTML 测试登录失败（401 错误）

**问题：** 用户名或密码不对

**需要的信息：**
- 数据库中 admin 用户的实际密码

**解决方法：**
- 重新运行 `重新初始化用户表.sql`

---

### 情况 3: HTML 测试登录成功，但获取用户信息失败（401）

**问题：** Session 没有正确传递

**需要的信息：**
- IDEA 控制台中两次请求的 Session ID

**可能原因：**
- Cookie 没有被浏览器保存
- Session 配置有问题

---

### 情况 4: HTML 测试全部成功，但前端登录失败

**问题：** 前端代码或配置有问题

**需要的信息：**
- 浏览器 Console 的错误信息
- 浏览器 Network 标签的请求详情

**可能原因：**
- 前端请求配置不对
- CORS 问题
- 前端路由问题
