## 🚀 部署步骤

### 第 1 步：数据库准备

在 MySQL 中执行：

```sql
USE `e-commerce-platform`;

-- 1. 确保 role 字段存在
ALTER TABLE `user` ADD COLUMN IF NOT EXISTS `role` VARCHAR(20) DEFAULT 'user';

-- 2. 更新测试数据
UPDATE `user` SET `role` = 'admin' WHERE `username` = 'admin';
UPDATE `user` SET `role` = 'user' WHERE `role` IS NULL OR `role` = '';
UPDATE `user` SET `password` = '123456';
UPDATE `user` SET `status` = 1;

-- 3. 确保 admin 用户存在
INSERT INTO `user` (`username`, `password`, `email`, `phone`, `status`, `role`)
SELECT 'admin', '123456', 'admin@example.com', '13800138000', 1, 'admin'
WHERE NOT EXISTS (SELECT 1 FROM `user` WHERE `username` = 'admin');

-- 4. 验证
SELECT id, username, password, email, role, status FROM `user`;
```

**预期结果：**
- admin 用户存在，密码是 123456，role 是 admin
- 其他用户的 role 是 user

## 🐛 常见问题排查

### 问题 1：登录后返回 401

**症状：** 登录成功，但获取用户信息返回 401

**原因：** Session 没有正确传递

**解决方法：**
1. 检查浏览器 Network 标签
2. 确认登录响应有 `Set-Cookie: JSESSIONID=...`
3. 确认后续请求有 `Cookie: JSESSIONID=...`
4. 清理浏览器缓存和 Cookie

---

### 问题 2：管理员统计数据不显示

**症状：** 管理员首页统计数据都是 0

**原因：** 后端接口调用失败

**解决方法：**
1. 打开浏览器 Console 查看错误
2. 检查 Network 标签的 `/api/admin/stats` 请求
3. 如果返回 403，说明权限不足
4. 如果返回 500，查看后端日志

---

### 问题 3：修改用户信息失败

**症状：** 点击保存后没有反应或报错

**原因：** 接口路径不对或参数错误

**解决方法：**
1. 检查 Network 标签的请求
2. 确认请求路径是 `/api/user/update`
3. 确认请求方法是 PUT
4. 确认请求体包含正确的字段

---

### 问题 4：密码修改失败

**症状：** 提示"当前密码错误"

**原因：** 输入的旧密码不正确

**解决方法：**
1. 确认当前密码是 `123456`
2. 如果忘记密码，在数据库中重置：
   ```sql
   UPDATE `user` SET `password` = '123456' WHERE `username` = 'admin';
   ```
